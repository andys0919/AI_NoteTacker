## 會議紀要
### 主題一：整體流程與啟動條件
- **兩階段啟動流程：**
    - **第一階段（系統啟動）：** 操作員 (OP) 在 UI 介面按下 "Play" 按鈕，啟動整個系統。此時系統進行復位與自檢。
    - **第二階段（生產啟動）：** OP 將機箱推至定位後，按下實體雙按鈕，機箱進入生產區，開始後續掃描與組裝。正常生產時，OP 不應操作 UI。
- **啟動前置檢查（自檢）：**
    - 系統啟動時（第一階段），需進行初始化自檢。
    - 檢查項目包含：
        1.  傳送帶 (conveyor) 與入料口感測器處必須為空，防止卡料或碰撞。
        2.  2D 相機確認左右入料盤（例如共 88 顆）是否備妥（是否有空位、方向/反放、彈片是否壓下）。
        3.  感測器檢查 3 個 NG 料盤是否已放置到位且為空。
    - 若任一檢查失敗，流程將終止並跳出彈窗通知人員處理。
- **結論：** 確認採用兩階段啟動模式，自檢於系統啟動時執行，確保生產前的安全與物料準備。
### 主題二：色片（舌片）與條碼掃描邏輯
- **舌片掃描流程：**
    - 3D 相機完成機殼位置補正後，機械手掃描「舌片」（治具/卡匣）上的條碼。
    - UI 介面可對應 6 個舌片，讓使用者勾選當前要組裝的項目。
    - 流程順序調整為：3D 定位 → 掃描舌片 ID → 執行入站（move in）指令將資訊傳送至 MES/MVS → 接收 MES/MVS 回傳的必要資訊（如 poker id）。
- **硬碟條碼規則取得與比對：**
    - 入站成功後，系統發送 API 2 (減料規則) request 給 MES/MVS，以取得本次安裝所需之硬碟條碼規則。
    - 系統解析規則後，開始取料。機械手以「飛拍」方式讀取硬碟條碼。
    - 每次取料後、插入前，系統需依規則比對條碼正確性。
        - **條碼正確：** 插入硬碟。
        - **條碼不正確：** 放入 NG 料盤。
- **結論：** 確認「先掃舌片、再入站、後取規則」的流程。接受為確保製造系統一致性，規則比對可能導致 Cycle Time (CT) 增加。
### 主題三：異常處理與復歸機制
- **硬碟插入與繫結失敗：**
    - **插入失敗：** 若硬碟無法插入（如碰撞），Force Sensor 將觸發系統跳停。人員手動排除障礙後，需按雙按鈕重啟，系統將跳過失敗槽位，從下一個槽位繼續作業。
    - **繫結失敗：** 每成功插入一顆硬碟，系統會發送 API 訊息給 MES 進行物料繫結。若 MES 回傳繫結失敗，將停機通知人員處理。
- **斷電/當機復歸：**
    - 為應對生產中斷（如當機、跳電），需記錄機械臂當前進度（如第幾排第幾顆），以利復歸後繼續作業。提議將進度記錄於 INI 檔或更可靠的 PLC 中，待設計端確認。
    - 復歸後，系統將繼續處理皮帶上未完成的料件，而非清空。
- **NG 料盤處理：**
    - NG 料盤上限為 3 片。若達到上限，整機將停機並通知人員清空。
    - NG buffer 的檢查時機為：裝置初次啟動時、NG 料盤滿載時。正常連續生產或工位切換中不重複檢查。
- **結論：** 異常停機後由人員介入，並透過雙按鈕重啟以確保安全。系統需具備狀態記錄能力，以支援斷點續作。繫結失敗、NG 滿盤等關鍵異常會觸發停機。
### 主題四：UI 介面與系統設定
- **狀態顯示與連線監控：**
    - UI 需顯示裝置運作狀態、三色燈號、MES 連線，以及所有相機（2 支用料檢測、2 支 3D 定位）、機器人的連線狀況。任一裝置連線失敗，流程即判定 fail。
- **入料盤監控方式：**
    - 取消原先的即時監控概念。改為在「啟動前」或「換盤使用前」對料盤進行一次性全面檢查。若發現異常（空位、反放等），以彈窗提示問題位置。
- **產線設定彈性：**
    - UI 介面需支援彈性設定，可讓使用者勾選裝置對應的產線數量（如 1-6 條）。UI 需同步顯示對應數量的 slot。
- **擴充性與客製化：**
    - 未來若需支援不同機箱規格（如 3x8、橫插）或自訂插入順序，將視為新專案或下一版本功能，需額外評估。現行版本不實作。
- **結論：** UI 介面以狀態顯示和異常彈窗為主，取消即時監控。系統需保留設定彈性，但超出 SOW 的客製化需求將另行評估。
### 主題五：變更管理與溝通
- **規格變更流程：** 執行端反映規格多次變更導致重工。會議同意，未來變更需先提報並由更高層討論決策後，才能進入開發，避免重複改動。
- **溝通渠道：** 將透過會後 email 作為變更溝通與確認的正式渠道。
- **SOP 衝突：** 針對製造端希望「不停機補料」以提升稼動率的需求，與現有安全流程（停機入料、啟動前檢查）存在衝突。此議題需與製造端達成共識並訂定最終 SOP。
- **結論：** 建立正式的變更審核機制。關鍵作業流程需跨部門協調，達成共識後再定案。
